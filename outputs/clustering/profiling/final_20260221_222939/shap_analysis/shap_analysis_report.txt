2. Methodological Note: Built-in vs SHAP Importance
   ----------------------------------------------------------------------------
   SHAP values differ from built-in methods for important reasons:

   Built-in Feature Importance (Algorithm-Specific):
     • Random Forest: Gini impurity reduction (how much each feature
       decreases node impurity during splits)
     • XGBoost: Gain (average improvement in loss function from splits)
     → These measure SPLITTING UTILITY, not true predictive importance
     → Can be biased by feature cardinality and correlation structure

   SHAP Importance (Game-Theoretic Attribution):
     • Based on Shapley values from cooperative game theory
     • Accounts for ALL feature interactions (not just pairwise)
     • Model-agnostic: Comparable across different algorithms
     • Satisfies desirable properties: efficiency, symmetry, dummy,
       additivity
     → Measures TRUE CAUSAL CONTRIBUTION to predictions

   Why Rankings Differ:
     • RF: Gini says 'ses_vulnerability' is #1, SHAP says 'chronic_disease_burden'
     • XGB: Gain says 'chronic_disease_burden' is #1, SHAP says 'ses_vulnerability'

   Example: A feature used early in many trees (high Gini/Gain) may have
   lower SHAP if other features capture the same information more precisely
   through interactions. SHAP decomposes credit fairly across all features.

   → Recommendation: Use SHAP rankings for interpretation, built-in metrics
     for computational efficiency during training.
